# Complete character custody and authoring

The catalog offers **Import complete DL1 character**. It creates a local `.dlrmodel` directly from the retail decoder. Blender is not involved in that import. The original resource bytes, archive/item/chunk metadata including opaque hashes and unknown fields, original material database, referenced texture resources, decoded LOD geometry, bone frames and bounds, weights, morph channels and deltas remain in the package.

Schema 8 supports binary FBX and stock-character sources. Schemas 1 through 7 still migrate on load; schema 7 authored layers are retained. The common surface representation is reused by preview and model output. Its historical FBX type names do not imply an interchange conversion. Full geometry revisions preserve attachments and manually authored or transferred shapes alongside the immutable source.

## Stock actor edits

Choose **Standard human NPC** when importing a model used by that actor class. Actor source review accepts exact `Model` / `Mesh` declarations and native `PresetDef` / `Preset` / `SetField("MeshName", ...)` sources. Choose the intended preset when several presets use the same mesh. The package keeps the complete preset file; only the selected preset's supported resource fields enter its reviewed source receipt.

To add an accessory, select its parent bone and use **Add attachment mesh**. In **Attachment material**, choose the accessory material and an original retained material, mark **Reviewed**, then use **Assign material**. Assignment preserves the original surfaces and face channels, archives replaced accessory material data, and supports Undo/Redo. Save and reopen the project before exporting the final candidate.

## CLI

Use `character inspect`, `character add-attachment`, `character assign-material`, `character export-neutral` and `character import-sculpt` for headless authoring. The UI and CLI share the same sculpt reader and expression transaction. See [Character commands](DL1_CHARACTER_CLI.md).

Use `app list`, `app status`, `app open`, `app save` and `app close` to control a running ReAnimated instance. Save As copies local project assets with their recorded identities and rolls back new copies when publication fails. See [Running app controls](DL1_APP_CLI.md).

Use `material-graph inspect` and reviewed `material-graph merge` to compare and stage compiled graph additions. See [Material graph commands](DL1_MATERIAL_GRAPH_CLI.md).

## Character panel

Use **Character systems** from the guided setup screen. The panel lists each subsystem, original resource identities and dependencies, and exact original morph channel/surface/LOD bindings. Missing, ambiguous and unsupported dependencies block complete character output. Identical blocker messages are summarized once; the full resource inventory retains every source identity and parent reference. Enter exact catalog companion roots to resolve their source dependency closure. Filename similarity is not evidence of an association. Conditional detached-part names can resolve to exact compiled mesh identities as candidates when loose sources are absent. Discovery retains every generated name and catalog provider alternative; finding a compiled mesh does not select the native filename branch. Script references beginning with `./` or `../` resolve lexically against the declaring virtual directory and must stay inside the virtual root. These paths use exact catalog identities, with no basename fallback; crossing the declaring provider remains reviewable. Original quoted text is retained. This source-custody rule does not prove that a particular native parser expands the include. Native auto-cloth, standard-human ragdoll and global mimic candidates are collected with explicit review status. Cloth can be configured explicitly; ragdoll depends on actor class/game mode; FED selection uses a supplied or model-associated name. No universal mesh-stem FED or ragdoll rule is inferred.

Use **Review actor source association** to select a retained actor definition, its exact Model/Mesh declaration and its enclosing source scope. Sibling actor/model references and unsupported calls remain unverified leads. Reviewed tokens are saved with the source provider, fingerprint, content hash and original spans, and are revalidated on package reopening and export. Editing or renaming the actor source invalidates its review. Source review is one undoable model edit; it does not prove native class defaults, resource loading or execution. When adopting original systems to a custom target, original reviews are archived as reference provenance and must be reviewed again for the target.

Conditional suggestions are retained in the inventory and are not automatically entered as selected roots. Re-resolving a companion promotes only an explicitly selected, unchanged exact source; unrelated ambiguous candidates remain review-blocked. Original archives and authored source edits survive resolution, and stale provider/source/content identities fail without replacing the current package. Discovery scan bounds and unsupported reference diagnostics also remain blockers until corresponding evidence resolves them. Global mimic custody alone does not complete the selected actor's FED and mimic-set association.

The material database is preserved as an original hashed external resource. Complete import also gathers each declared mesh and skin material record with its exact provider identity, payload and texture references. Missing records remain explicit dependencies. For an accessory, reviewed material assignment can reuse an original native slot while keeping original rows and skin mappings. The replaced accessory material and unused texture bytes are archived in the package. Portable DDS previews contain the original decoded base-mip blocks; the original texture resources remain in companion custody. Original material references remain the references used by native output. Original skin variants retain their full material inventory and entity-name mappings. Supported variants generate a text `.skn` sidecar alongside CHR transform variants; the compiler verifies names, material substitutions, visibility flags and counts independently. Exact tag/color bytes, optional skin strings and surface rows are retained. A bounded source mapping covers verified colors, empty tags/strings, and supported surface representatives; compiler readback compares every mapped value. Unknown tags, strings, groups, surface IDs or flags remain preserved and export-blocking. New attachment material slots extend each skin with explicit identity substitutions while the original rows remain unchanged.

Select a bone to inspect its local center and full X/Y/Z sizes. Original matrices and bounds, including zero-sized original pivots, remain unchanged by default. **Fit bounds candidate** computes a candidate from retained weights. Applying a candidate or a manual edit records an undoable model change and invalidates prior build/runtime evidence. These coordinates are explicit source-local axes; Height/Width and native shape dimensions require the controlled measurement tests.

Compiled material names may have multiple instances with distinct load values. Skin readback checks every indexed instance, full replacement coverage, consistent replacements and self-slot identity. It rejects missing, repeated or ambiguous mappings.

## Expressions and attachments

For a custom model, load an original character reference package and use **Attach original systems to custom character**. The target source, geometry and existing channels remain unchanged; source resources and the original decoded reference are archived. Transferred native systems remain review-blocked, and original morph names without authored target channels remain unmapped. Existing character inventories are protected from replacement.

Use **Open face expressions and sculpting** at the top of Character systems to reach the reference and shape controls. Load an original morph reference package, choose its face surface and expression, and choose the custom target face surface. Use the original reference, accepted target and target-neutral preview controls to compare the same expression on the intended model. The preview subject identifies which geometry is displayed. Export the selected current target neutral face as OBJ directly from this panel. Sculpt its positions in meters, preserve vertex order and triangle topology, and import the OBJ or binary FBX under the original expression name. The neutral export does not edit the package or its history. Manual sculpt imports must retain the selected target topology and control-point ordering. FBX corner splits are supported when the original control-point provenance and ordered triangles match; changed topology, conflicting corner positions and missing points are rejected. Original names/descriptors remain authoritative. Existing expressions require an explicit keep or replace choice. Keeping a shape also keeps its original authoring receipt and does not create an undo entry. A zero-delta placeholder is rejected for a new expression and for a replacement. Keeping an existing shape preserves its original data and receipt.

Choose **Pick original reference point** and **Pick target point** to inspect each selected neutral face. Click its corresponding landmark: the triangle is outlined and its nearest render corner is marked, with exact transfer indices in the status text. Add a landmark or triangle pair, or add a target point to the reviewed region or neutral locks. These controls author correspondence inputs without editing geometry; changing the face, expression or model invalidates picks. Middle drag and the wheel adjust the view while selection is active. Assisted transfer uses reviewed triangle correspondences, source deformation gradients and a weighted constrained solve on the target neutral topology. Reviewed face-region masks, weighted vertex landmarks and triangle pairs constrain the proposal. Locked vertices remain neutral. Changing the selected face, correspondence, region or locks invalidates a pending proposal. Accepted receipts retain the original channel index, target slot, fingerprints, exact deformation-payload hash and reviewed constraints. Changing the nonzero deltas or target channel mapping invalidates the review. Older receipts without a deformation hash remain readable with their geometry and provenance preserved, but require fresh review before standard export. Saved expression reviews are shown in the face panel. Changing the target neutral positions, triangle topology, surface identity or reviewed target indices invalidates their accepted state on geometry capture and reopening. The original receipt and expression deltas remain preserved; standard export refuses stale reviews until the expression is authored and reviewed against the current target. Review eyelids, jaw/lips, combined expressions, seams and unaffected regions before accepting a proposal. A source/target topology or neutral-position change invalidates the proposal. The algorithm is independently implemented; no research implementation or dataset is bundled. See [Sumner and Popovic](https://people.csail.mit.edu/sumner/research/deftransfer/).

Rigid attachments use a selected parent bone. Compatible skinned attachments retain their local palette indices and map palette entries to the target hierarchy. Different bind frames require a reviewed binding transfer first. Existing character surfaces, facial channels and companion records are retained.

## Gathered effects

The retail catalog expands FX aggregates into exact virtual `.fx` identities with their original pack priority. Import retains each selected definition's stored name, signed kind, source text, byte extent and SHA-256, plus one copy of each original aggregate. Nested quoted effect references resolve by exact global name. Particle Material calls resolve their first argument through the selected retained material provider; exact payload extents, sampler/load fields and full native texture items enter the package. Unknown definition kinds remain in the package.

Package saving verifies that each definition still matches its retained aggregate. Authored edits archive the original receipt; derived sources use their updated identity. The CLI inspection report includes these receipts. Malformed aggregates produce catalog diagnostics and prevent a partial catalog snapshot from being persisted.

The official model compiler links one gathered FX aggregate and the retained complete texture envelopes into its output RPack and deployed mesh object, then compares every definition and texture item through semantic readback. The compiler receipt records effect, texture and item counts. Material publication stages an opaque union of the retained source graph and the project database. Destination records and stored extents remain intact; differing duplicate keys block publication. Only the documented zero padding of string and input-attribute records can compare as equivalent. The compiler rereads the union and verifies exact material payloads and native texture lookup identities. Existing SDK reference/debug companions are retained from the original staged material output; importing runtime graph bytes does not generate new source bookkeeping. Later SDK material rebuilds still require a matching source graph and its companion files. Complete-character export also retains the remaining dependency checks.

## Detached assets

Literal body-element mesh filenames can resolve to exact compiled mesh stems when a loose source is absent. Conditional relic filenames remain candidates until their active relationship is selected. Import retains every native item, its routing and hashes, then decodes the material inventory and retains its material and texture dependencies. Unknown layouts stay in the package with an export check.

Typed compiled meshes appear in detached-asset choices even when their catalog names have no filename extension. The compiler writes their complete standalone mesh objects, links their resources into the character pack, and verifies every item. Deployment stages each named object through the existing asset transaction. Original variants and opaque native data remain unchanged.

## Ragdoll and damage source authoring

Ragdoll PHX, body-element BEL and damage-patch SCR readers retain comments, unknown calls, includes and source text. Ragdoll is a separate typed contract from cloth. Use the explicit Ragdoll physics, Body regions and gore, or Damage patches buttons to choose the system. A selected physical-bone group collects only exact typed bone and joint-pair references, including its joints, collision and synchronization calls. An exact unique hierarchy match selects that bone and shows its authored bounds/local axes. Missing or ambiguous matches are reported; global and unknown settings remain in All original settings. No native capsule/sphere dimensions are synthesized from those bounds. The editor groups original settings by physical bone, body region and damage patch, shows their linked references and offers existing replacement identities. It exposes source settings and verified references, including physical bones, shape tokens, relative mass, scale, joints, exclusions, synchronization, helpers, mesh disable lists, detached-part physics/effects and damage transforms.

The body-region relationship list distinguishes the original-body hide list from the detached-part hide list and shows exact helper, physics and effect references. **Update selected relationship only** edits one recognized call/argument; **Rename all matching verified references** remains the separate global operation. Proposed edits reset their review when the selection or value changes. Conditional relic mesh names remain unverified and cannot be edited through the local relationship control.

For an authored region assembly, import artist-made cap geometry, choose an existing BodyElement, and add its exact cap surface IDs and retained detached, physics and effect resource IDs. Multiple selections are supported. The original character root is excluded from detached-part choices; supply a separate retained detached model. Review both geometry and relationships before recording the undoable assembly. The package retains its source hash, helper frame, target geometry fingerprint, body/relic hide roles and selected asset hashes. Expand Details on a saved review to inspect its exact cap surfaces, detached models, physics/effects and both hide lists after reopening. Source, geometry, helper-parent or asset changes invalidate that review while preserving its original record. The neutral visibility preview hides only the declared original-body entities; it does not simulate native cuts, detached-part motion or effects. A region assembly review does not resolve conditional relic naming or confer Player acceptance.

Source edits verify the expected hash/token before applying. The first edit archives the original bytes; later edits retain that archive. Resource renames update recognized consumers together and refuse unknown old-name consumers rather than leave dangling references. Failed transactions retain the prior package. Cut/cap geometry must be supplied by the artist; this workflow does not generate it automatically.

Source preservation alone does not verify native semantics. In particular, a relic name can select different mesh filenames according to runtime branches. Original variants and opaque relationships must be resolved before complete/game-ready output is accepted.

## Acceptance boundary

The source writer, official compiler inputs and previews share the corrected palette-local skin-index convention and bone-bound data. Standard complete output rejects unresolved character dependencies. Diagnostic compiler controls can be generated for offline investigation and are not deployment acceptance.

Release acceptance still requires compiled semantic readback, the identity of the actual loaded resources, controlled native collision/ragdoll measurements, head and both left/right limb damage scenarios, cut/cap visibility, detached-part physics/effects and repeated damage. Stock reuse must prove an unchanged control and an added attachment preserve original channels, deltas, weights, bounds, variants and companions. Custom-face acceptance also requires the expression and mimic/FED checks. Independent source-blind UI QA and the video guide remain separate requirements.

The private external-model compiler acceptance check accepts `DLR_MODEL_COMPILER_WORK_ROOT` for an explicit compact staging directory. Retain failed compiler logs when comparing staging locations; a written object with a rejected exit status is not published.

Public tests use generic synthetic fixtures. Stock packages, measured results, source paths and exact local native audits belong to private validation data.
