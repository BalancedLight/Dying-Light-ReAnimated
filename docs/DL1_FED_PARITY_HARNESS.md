# Historical DL1 FED compatibility fixture provenance

> **Historical background only.** The C# application, package, validation scripts, and GitHub Actions do not install or execute Python. This document records the provenance of a checked-in static C# compatibility fixture; the former live differential wrapper was retired.

## Scope

The first-release FED gate is a bounded, redistributable differential control
for the Dying Light 1 face-expression container:

```text
Int32 expression count
repeated:
  UInt16 UTF-8 expression-name byte count
  expression-name bytes
  Int32 morph-weight count
  repeated:
    UInt16 UTF-8 morph-name byte count
    morph-name bytes
    IEEE-754 float32 weight
```

All integer and floating-point fields are little-endian. The checked fixture
contains only bytes generated by the repository oracle. It contains no retail
FED, mesh, animation, texture, or other proprietary payload.

The tracked legacy Python application had no FED reader or FED expression domain. This fixture was historically reviewed with a small independent decoder, but it is now retained solely as static C# test input and has no Python module or external-path dependency.

## Accepted controls

`tests/fixtures/dl1_python_csharp_fed_parity_v1.json` records two generated
inputs:

1. A canonical ordered document with an empty `_NONE` expression and finite
   positive, negative, above-one, and negative-zero weights.
2. A compatibility document with case-insensitive duplicate expression and
   morph names.

`PythonFedParityTests` requires C# to agree on:

- expression and weight source order;
- exact UTF-8 names;
- every weight's exact float32 bit pattern, including negative zero;
- compatibility-mode `FED001` and `FED002` diagnostics;
- case-insensitive first-expression lookup;
- non-destructive layer mapping, case-insensitive duplicate-row summation,
  target-rig track order, missing-source diagnostics, and compatibility counts.

The layer control does not clamp or rewrite authored FED values. It proves only
the named synthetic mapping; it is not a model-family alias profile.

## Rejected controls

The independent Python decoder and C# reader both reject the checked cases for:

- truncated, negative, and excessive expression counts;
- empty, whitespace-only, invalid-UTF-8, embedded-NUL, and oversized strings;
- negative and excessive weight counts;
- empty morph names;
- non-finite and truncated weights;
- trailing bytes in strict mode;
- duplicate expressions and morph rows when strict duplicate rejection is
  enabled.

The test compares the acceptance decision and an actionable diagnostic
category. Exception class names are not required to match across languages.

## Current validation

`PythonFedParityTests` reads the checked-in FED fixture as static compatibility data. Run the Hermetic C# tier to exercise it:

```powershell
.\tools\validate_csharp.ps1 -Tier Hermetic -Configuration Release
```

Package provenance includes the C# tests, fixture tree, and documentation only; it does not include or run a Python oracle.## Boundaries

This control closes the bounded binary-reader and expression-normalization
seam. It does not prove:

- that the legacy Python app had FED support;
- every possible Unicode case-folding equivalence;
- every retail model-family mapping;
- morph-delta rendering or a FED visual golden;
- live Dying Light 1 expression behavior.

Installed retail corpus and exact-model compatibility tests remain
non-redistributable acceptance evidence and embed no retail bytes.
